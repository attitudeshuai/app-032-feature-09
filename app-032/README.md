# 花灯骨架放样与蒙面裁片 · Lantern Frame Lofting

纯前端工具：选灯型 → 填直径/高度/收口 → 出「每根竹篾截多长、弯什么角度」的骨架件表、带缝份的蒙面裁片、以及可 100% 打印的 1:1 放样图与备料单。无后端、无网络请求，断网可用。

## 技术栈

- Vue 3（`<script setup>` 单文件组件）+ TypeScript + Vite 6
- 状态：Vue 自带 `ref / reactive / computed / watch`（无 Pinia / Vuex）
- 额外依赖仅 `vue-router` 4（规格书要求的 6 个路由）
- 手写 CSS；无 UI 组件库、无图表库、无游戏引擎/物理库
- 字体、灯型数据包（`src/data/lantern-types.json`）全部本地打包，无外网 CDN

## 自检结论 ↔ 参数 对应关系

每条自检结论（CHK-01~08）都携带「相关参数」列表，**唯一来源是 `src/core/check-map.ts`**：
页面自检、骨架件表 / 蒙面裁片页底部的结论、备料用量联动、三份导出 CSV 的自检结论块、
本机存档里的自检快照，全部从同一张表取参数名与排队，改一处别处自动跟着变。

- **点一条没过的结论** → 按对应关系落到相关参数所在页面（参数与预览页 / 1:1 放样图页），
  相关参数红框标出；每个参数按影响大小排队（●1~5），并注明改它会牵动哪些别的结论。
- **参数一改即重核**：未过名单实时更新——转通过的自动移走，新冒出来的打「新」。
- **结论版本号**：由参数 + 结论状态算出，页面自检、导出单子、本机存档带同一个号；
  哪一份已导出的单子指的仍是老结论，会在各页点名（哪一份、何时导出、旧版本号），提示作废重出。

**取舍（两条路选一条，认下代价）**：选「每条结论列出全部相关参数、按影响大小排队」——
一个不漏；代价是让出「去处的唯一」：一条结论同时指向几个参数，改一个又会牵动别的结论，
来回试的次数变多。未选「每条结论只认一个主参数」：去处唯一、好点好记，但起作用的参数
可能不在主参数上，照着改未必能过；若按那版对应关系存了档、导了单子，存档参数与已发出的
单子图纸都得作废重出，照旧参数裁好配好的料要重来。

**面积核对分档与精度**：比值 = Σ裁片净面积 / 灯体表面积，按百分数分档——
合格档 [97.00%, 103.00%]（通过）、临界档（偏差 ≤ 5.00%）、超差档（5.00%~15.00%）、严重超差档（> 15.00%）；
旋转体超差时，母线等分数按整数往上加，**首个让比值落回容差的等分数**即为建议值（裁片与参考面积都按候选等分重算）。
单位与精度：长度 mm 保留 1 位小数；面积 m² 保留 3 位小数；比值百分数保留 2 位小数。

**旧存档迁移**：本机存档（version 2）载入时，缺了的参数按写明的默认值补上再参与核对
（工艺参数取 `lantern-types.json` 的 craft 段，其余见 `store.ts` 的 migrateLantern），
缺的项在首页「旧存档补齐说明」逐条列出。

## 启动

```bash
npm run dev        # http://127.0.0.1:5173
npm run build      # vue-tsc --noEmit && vite build
npm run preview

```

## Docker 构建

```bash
docker compose build
docker compose up -d            # http://localhost:8112
curl http://localhost:8112/healthz
docker compose down
```

多阶段：`node:20-alpine` 构建 → `nginx:1.27-alpine` 只托管 `dist/` 与 `nginx.conf`（SPA 回退、哈希资源 immutable、index.html no-cache、gzip、SVG MIME、`/healthz` 健康检查）。
